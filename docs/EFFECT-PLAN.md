# Effect — план улучшений и отладки

Цель: Effect должен работать плавно на телефоне, выглядеть цельно в каждом месте и быть полноценным продуктом — студией, в которой из одной фразы получается сайт, лендинг, презентация или игра, которую можно доработать и забрать.

Каждый шаг заканчивается проверкой. Если шаг что-то ломает, он откатывается, а не «чинится сверху».

Основные файлы:
- лендинг — `components/effect/EffectHome.tsx`, `components/effect/PrismHero.tsx`, `app/effect-home.css`;
- студия — `components/effect/Studio.tsx`, `app/effect.css`;
- движок — `lib/effect/*`;
- API — `api/effect.mjs`;
- артефакт — `https://claude.ai/artifact/1nkCUqnQPttp2ajM5EmffP`.

## Часть 2. План отладки

### 2.1 Инструменты

- Playwright с профилями `iPhone 13`, `Pixel 7`, `iPad Pro 11` и CPU throttling 4× через CDP (`Emulation.setCPUThrottlingRate`).
- CDP `Performance.getMetrics` (LayoutCount, RecalcStyleCount, ScriptDuration) и `Tracing` для профиля кадров.
- Счётчик FPS в странице (rAF за 2 с) и PerformanceObserver для `longtask`, `largest-contentful-paint`, `layout-shift`.
- Скриншоты всех экранов с шагом в высоту экрана и сводные листы (как сейчас) для поиска кривых мест.
- Консоль: ни одной ошибки `pageerror` или `console.error` ни на одной странице.
- Lighthouse (мобильный профиль) для `/effect` и `/effect/studio`.

### 2.2 Порядок отладки производительности

1. Снять профиль 5 секунд в герое без прокрутки. Найти: перерисовки (Paint), композиционные слои, вечные rAF.
2. Снять профиль прокрутки всей страницы. Найти: layout thrashing, тяжёлые фильтры, iframe.
3. Отключать слои по одному (обводка, луч, веер, вспышка, параллакс, пыль, размытие фона) и мерить FPS. Записать вклад каждого слоя.
4. Чинить по убыванию вклада. После каждого исправления — повторный замер.
5. Отдельно проверить iframe примеров: FPS с ними и без них.
6. Повторить на студии: генерация, переключение устройств, режим «Текст», вкладка «Код» с большим HTML.

### 2.3 Порядок отладки вёрстки

1. Проверить ширины 360, 390, 414, 768, 1024, 1280 и 1440 на каждой странице: `scrollWidth - innerWidth` должно быть 0.
2. Найти обрезанный текст: элементы, у которых `scrollWidth > clientWidth` без `overflow` прокрутки.
3. Найти наложения: пересечения прямоугольников соседних блоков в одном контейнере.
4. Проверить зоны нажатия ≥44px на телефоне.
5. Проверить безопасные зоны iPhone: элементы у краёв не уходят под «чёлку» и полосу «Домой».
6. Сверить со сводными скриншотами, отметить каждое кривое место, исправить, повторить.

### 2.4 Функциональная отладка

- **Студия:** создание каждого типа, 10 команд чата, отмена до начала, переименование, удаление, перезагрузка (проекты на месте), режим «Текст» (мост не утекает в HTML), вкладка «Код» (правка применяется).
- **Движок:** темы × типы × языки, команды «добавь / убери», цвета, шрифты, тема, игры (смена типа, скорость), слайды (добавить / удалить).
- **API:** без ключа (503, модели выключены), с ключом (поток, отказ, обрезка, лимит 429), отмена запроса.
- **Артефакт:** нет внешних запросов кроме Google Fonts, нет `alert`/`confirm`/`print`, копирование работает, `localStorage` в try/catch.
