# Effect — замеры производительности

Методика (план, часть 2.1–2.2):

- Chromium из Playwright (headless), профили `iPhone 13` и `Pixel 7` из `playwright.devices`, плюс те же профили с CPU throttling 4× через CDP `Emulation.setCPUThrottlingRate`, плюс компьютер 1440×900.
- Страница грузится, через 2,5 с снимается 5 секунд героя без прокрутки: FPS (число кадров `requestAnimationFrame`), худший кадр, `LayoutCount` и `RecalcStyleCount` из CDP `Performance.getMetrics`.
- Прокрутка всей страницы за 10 с (`scrollTo` в каждом кадре): FPS, число кадров длиннее 34 мс.
- Отдельно — прокрутка блока «Живые примеры» за 4 с.
- `PerformanceObserver`: `longtask`, `largest-contentful-paint`, `layout-shift`; вес страницы — сумма `encodedDataLength` из CDP `Network`.
- Вклад слоёв: FPS героя в покое, когда один слой скрыт (`display: none`).

Headless-Chromium рисует программно, без GPU, поэтому абсолютные цифры ниже, чем на реальном телефоне, но относительное сравнение «до / после» честное: всё снято на одной машине одним скриптом. Скрипт замера — `perf.cjs` в рабочей папке сессии (в репозиторий не входит).

Что изменилось и почему:

- Герой: 3,9–27 → 59–60 FPS. Свет призмы — HTML-слои в координатах рендера 1536:864, анимируются только `transform` и `opacity`; обводка — вращающийся `conic-gradient` под запечённой маской `public/effect/prism-rim.webp`; веер и обводка ограничены своими bounding box, чтобы маска и `clip-path` покрывали меньше пикселей. Нет SVG-фильтров, SMIL и `mix-blend-mode`.
- В покое 0 пересчётов layout за 5 с (было 113–136): параллакс без вечного rAF, только на `scroll` / `pointermove` и только пока герой виден. Оставшиеся ~300 пересчётов стилей — это CSS-анимации света (композитор).
- Прокрутка: 25–29 → 60 FPS на телефонах, 3,9 → 55 FPS на 1440. «Живые примеры» — вкладки и один iframe, который создаётся только рядом с экраном и выгружается при уходе (в конце прогона iframe в DOM нет). Липкая секция 380vh убрана.
- Мгновенный движок вынесен в отдельный чанк (`engine-*.js`, 102 КБ) и грузится только когда блок примеров подходит к экрану; чанк `ui` на главной — 3 КБ вместо 105 КБ. Число запросов на старте 34 → 17.
- Вклад слоёв: на телефоне ни один слой больше не снижает FPS. На 1440 (программная отрисовка) заметен только луч (−9 FPS).
- Картинка героя: `<picture>` отдаёт телефонам 960px сразу, без второй загрузки; preload с `fetchpriority="high"`; CLS = 0.

LCP на сети 4G (iPhone 13, CPU 4×, элемент LCP — картинка призмы):

| Сеть | LCP `/effect` | LCP артефакта |
|---|---|---|
| «Быстрый 4G» (9 Мбит/с, RTT 60 мс) | 1380 мс | — |
| «Медленный 4G» Lighthouse (1,6 Мбит/с, RTT 150 мс), медиана 3 прогонов | 5760 мс | 740 мс |

Цель «LCP < 2,5 с на 4G» выполняется на быстром 4G и не выполняется на медленном профиле Lighthouse: картинка делит канал с общим для всего сайта CSS (327 КБ), фреймворком и пятью шрифтами корневого layout, которые предзагружаются на всех страницах. Это следующий шаг (разделение CSS и шрифтов по маршрутам), он затрагивает весь сайт Focus.
